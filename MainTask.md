4. Режимы интерфейса
    LIST:

    экран списка заметок (как список чатов)
    DETAIL:

    экран открытой заметки
    заметка редактируется сразу, без отдельного режима редактирования
5. Экран списка заметок (LIST)

    Окно узкое и вертикальное, визуально похоже на список чатов.
    Каждая заметка отображается как карточка/блок.
    В карточке есть троеточие (меню действий).
    Меню карточки содержит:
    Удалить
    Изменить название
    Нажатие на карточку открывает заметку на экране DETAIL.
    На экране списка стрелка “назад” не отображается.
    Троеточие (меню) на уровне экрана списка отображается.
6. Экран заметки (DETAIL)

    Заметка открывается на весь экран окна.
    В верхнем левом углу кнопка “назад”.
    В верхнем правом углу троеточие (меню).
    Слева от троеточия отображается Save.
    Ниже верхней панели:
    редактируемое название заметки
    строка тегов (теги отображаются плашками)
    текст заметки (редактируемый)
    Редактирование происходит сразу по нажатию на редактируемый элемент (без переключения режимов).
7. Поведение сохранения и навигации

    При нажатии “назад” на экране DETAIL:
    если есть несохранённые изменения, выполняется автоматическое сохранение,
    после успешного сохранения выполняется переход в LIST.
    Если автосохранение не удалось:
    пользователь остаётся на экране DETAIL;
    отображается сообщение об ошибке.
    Кнопка Save сохраняет текущие изменения вручную.
    После успешного Save отображается статусное сообщение.
8. Работа с тегами в заметке

    Теги отображаются как отдельные плашки (не строкой через запятую).
    Теги можно редактировать из экрана заметки.
    На уровне бизнес-логики при сохранении заметки:
    существующие теги должны переиспользоваться;
    отсутствующие теги должны создаваться.
    Для сравнения тегов должно быть зафиксировано правило:
    либо exact-match,
    либо normalized-match (trim/lowercase).
    Рекомендуется normalized-match.
9. Функциональные операции (MVP)

    Создать заметку
    Открыть заметку по нажатию из списка
    Обновить заметку (название, текст, теги)
    Удалить заметку
    Переименовать заметку из меню списка
    Получить список заметок
    10. Поведение при ошибках
    Ошибки сервиса (not found, duplicate, validation) не должны ломать UI.

    UI должен:

    показать понятное сообщение пользователю;
    сохранить рабочее состояние экрана;
    не обращаться напрямую к репозиториям.


    Правила переходов (самое важное)
    Нужно письменно зафиксировать:

    openNote(id):
    грузим заметку из сервиса
    заполняем черновик
    mode = DETAIL
    dirty = false
    changeTitle/content/tags:
    меняем черновик
    dirty = true
    save:
    вызываем сервис
    при успехе dirty = false, обновляем список/текущую заметку
    при ошибке остаёмся в DETAIL, пишем errorMessage
    back:
    если dirty = false -> просто LIST
    если dirty = true -> автосейв, и только потом LIST
    если автосейв упал -> остаёмся в DETAIL
